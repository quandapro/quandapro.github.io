A drop-in base URL

how it works

Agents keep their normal API format. You change one base URL and one key; Leash forwards the request and streams the answer back while it meters tokens and cost.

  1. agent
  2. auth
  3. redact
  4. loop check
  5. budget
  6. provider
  7. meter
  1. Auth. Only lsh_ keys are accepted; the real provider key is decrypted on the server for this one call.
  2. Redact. Secrets in user and tool-result content are replaced. Assistant turns and thinking blocks are left alone, so prompt caching and extended thinking keep working.
  3. Loop check. The rules read the conversation history the agent sends, so they need no stored state and survive restarts.
  4. Budget. A capped worst-case estimate is checked against key and global limits before anything is forwarded.
  5. Meter. Token usage is read from the stream itself and priced per model. Leash stores counts, costs and tool names, never full prompts.

Running in five minutes

any server with Docker

The production compose file runs Leash behind Caddy, which gets a TLS certificate for your domain automatically. The container runs as non-root with a read-only filesystem.

1

Deploy

shell
git clone https://github.com/quandapro/leash && cd leash
cp .env.example .env    # set LEASH_ADMIN_TOKEN, LEASH_SECRET, LEASH_DOMAIN
docker compose up -d

Then open your domain, sign in with the admin token, add a provider key and create one Leash key per agent.

2

Claude Code

shell
export ANTHROPIC_BASE_URL=https://leash.example.com/anthropic
export ANTHROPIC_API_KEY=lsh_your_leash_key
2

Codex CLI

~/.codex/config.toml
model_provider = "leash"

[model_providers.leash]
name = "Leash"
base_url = "https://leash.example.com/openai/v1"
env_key = "LEASH_API_KEY"
wire_api = "responses"

Cline, aider, Continue, OpenClaw, Hermes and other OpenAI-compatible clients: base URL https://leash.example.com/openai/v1, API key = your Leash key. Subscription logins (Claude Pro/Max, ChatGPT Plus) can’t be proxied.
